PUESTO: Servicios Reunidos S.L. (Sep 2020 – Feb 2022)
Proyecto: "Missions" = tu TFG (Trabajo de Fin de Grado)
======================================================================
Aclaración tuya: el TFG es la app Missions más el portal de campañas. El repo
Campaigns_web solo contiene un README escrito en 2024 (por eso sus commits son de
esa fecha); el código original no está ahí. Las fechas ya son coherentes: la app
se desarrolló entre abril y agosto de 2021, dentro de este puesto.

1. ¿Qué producto o app hiciste?
   Plataforma de misiones para generar un dataset de imágenes:
   - App móvil Flutter para los usuarios: login, registro, edición de perfil y
     contraseña, lista de misiones en tarjetas, cámara y galería para hacer las
     fotos, guía de fotos y control de errores sin conexión. [REPO TFG/tfg_app]
   - Portal web de administración en Vue.js: el administrador crea, consulta y
     borra campañas, define misiones de tipo texto o imagen, elige puntos de
     venta con filtros combinables, ve los resultados por usuario y puede
     enviarle un email. [README Campaigns_web]
   - Detección de objetos con una red neuronal (Darknet/YOLO con scripts
     Python) para procesar las imágenes. [REPO TFG/darknet]
2. ¿Para quién? (cliente/sector y cuántos usuarios)
   Campañas en puntos de venta (PDV) con puntos de recompensa por misión; en el
   backend hay categorías de PDV como hipermercados. [README, REPO]
   [FALTA] si era para un cliente real o un prototipo de TFG y cuántos usuarios.
3. ¿Cuál era tu parte exacta?
   Todo el TFG, tú solo: app Flutter (44 de 49 commits son tuyos, abril–agosto 2021),
   portal Vue e integración de Darknet. [REPO, tu aclaración]
4. Resultados con números
   ~3.300 líneas de Dart repartidas en 12 pantallas y 4 servicios, sin tests
   automáticos (solo el test de ejemplo de Flutter). [REPO]
   [FALTA] nota del TFG, precisión del modelo o campañas de prueba, si las hubo.
5. Lo más interesante técnicamente
   Arquitectura:
   - Capas simples: pantallas en lib/pages, servicios en lib/service y modelo en
     lib/model. [REPO]
   - Estado global del usuario con scoped_model (patrón Model/ScopedModel), que
     notifica a todas las pantallas al cambiar token o perfil. [REPO]
   - Datos por GraphQL (graphql_flutter) contra un backend tipo Hasura: consultas
     de PDV por categoría y mutaciones para actualizar perfil y contraseña;
     autenticación y cambio de contraseña por REST con token Bearer. [REPO]
   - Sesión persistente con shared_preferences. [REPO]
   - Validación de formularios con DNI/NIE y email (dni_nie_validator,
     email_validator), indicadores de carga (flutter_spinkit) y foto de perfil
     con image_picker. [REPO]
   Nota: en el código Flutter no veo el envío de las fotos a la red neuronal;
   [FALTA] cómo llegaban las fotos al modelo (¿backend aparte?).
6. Tecnologías
   Flutter, Dart, GraphQL, REST, scoped_model, shared_preferences, image_picker,
   Vue.js, Python, Darknet/YOLO. [REPO]
7. ¿Se puede nombrar?
   El código es tuyo y lo puedes describir, pero no distribuir. El portal está
   bajo NDA según el README: no nombrar al cliente ni mostrar capturas.
   En la web enlazas solo el GitHub de Missions, que está bien.
